# 严格 JSON 裁决

## 目的
让主 agent 对直接调用的审查角色只做一次完整解析与字段校验，杜绝从自然语言推断通过。

## 逻辑
主 agent 对角色的完整最终回复整体执行一次 JSON 解析，要求结果是唯一、非空、非数组的对象，顶层字段与约定精确一致，字段类型、非空性与枚举合法，PASS 与 FAIL 的字段组合自洽。任何一步不满足即视为 FAIL，并把具体原因展示给用户；不截取片段、不用正则提取、不读首行或结论段。

## 约束
- C-1：当直接审查角色返回最终回复时，系统应对完整回复整体执行一次 JSON 解析，只接受唯一、非空、非数组且顶层字段精确匹配约定的对象。
- C-2：如果解析失败、回复含前后文字或围栏、字段增缺、类型或枚举错误、或 PASS/FAIL 与其他字段组合矛盾，系统应把门禁视为 FAIL 并显示具体原因，不得从自然语言中推断通过。

## 例子
角色回复在 JSON 对象前多了一句“审查完成：”，主 agent 整体解析失败，界面显示“解析失败：回复含前置文字”，流程停止。

## 验收
### AC-1 合法对象被接受  ← C-1
- 触发: 操作 让直接审查角色返回一个字段集合与语义均符合约定的 JSON 对象
- Given: 主 agent 正在等待该角色的裁决
- When: 角色调用结束
- Then: 系统依据该对象的 `verdict` 继续后续流程，界面没有解析或校验错误

### AC-2 偏差结果失败关闭  ← C-2
- 触发: 操作 让直接审查角色返回带围栏、额外字段或 `verdict: PASS` 却带非空 `issues` 的回复
- Given: 主 agent 正在等待该角色的裁决
- When: 角色调用结束
- Then: 系统把门禁视为 FAIL，显示具体的解析或校验失败原因，后续动作没有执行
