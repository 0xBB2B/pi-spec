# Git 推送前审查门禁

## 1. 行为规则

当本地提交准备完成并即将发生远端写入时，系统应先启动 `pre-reviewer`，且在审查完成前不得推送提交或创建 PR/MR。

当 `pre-reviewer` 的第一个非空行精确为 `## 结论 PASS`、全部结果只有一个精确 PASS/FAIL 裁决行且待推送内容保持不变时，系统应允许继续推送提交并创建 PR/MR。

如果 `pre-reviewer` 返回 FAIL、未明确返回 PASS、输出格式不合规、不可用、执行失败或快照采集失败，系统应保留本地提交并停止流程，不得推送提交或创建 PR/MR。

当有效 PASS 绑定的提交标识、已跟踪改动、未跟踪文件路径或内容发生变化时，系统应使原审查结论失效，并在后续远端写入前重新完成提交与 `pre-reviewer` 审查。

系统应仅使用 `pre-reviewer` 执行强制审查，不得启动已删除的推送前审查流程。

当系统向远端推送时，系统应以取得有效 PASS 的提交标识作为固定推送来源，不得因当前分支随后变化而推送未审提交。

当系统准备创建 PR/MR 时，系统应确认远端来源分支仅指向取得有效 PASS 的提交；如果查询失败、来源不唯一、无法解析或提交不一致，系统应停止且不得创建 PR/MR。

## 2. 对外接口

- 触发入口：用户要求提交 PR、Pull Request、Merge Request，或调用 `/skill:git-push`。
- 审查顺序：本地 commit → 待推送内容快照 → 同步 `pre-reviewer` → 明确 PASS → 快照复核 → push → 本地复核与远端来源校验 → 创建 PR/MR。
- 明确 PASS：第一个非空行必须精确等于 `## 结论 PASS`，且全部审查结果只能有一个精确 PASS/FAIL 裁决行；空结果、前置文字、正文或引用中的 PASS、FAIL、多裁决或其他格式均不放行。
- 待推送内容：当前提交标识、相对该提交的全部已跟踪改动，以及所有未跟踪文件的路径和内容。
- 推送来源：取得有效 PASS 的固定提交标识；远端目标为当前来源分支的完整远端引用，不使用强制推送。
- 创建门禁：远端来源查询必须返回唯一记录，且来源分支与提交标识均精确匹配有效审查快照；GitHub 与 GitLab 创建命令复用同一已校验来源分支。
- 失败结果：保留本地 commit，显示停止原因，不执行后续 push 或 PR/MR 创建，也不由主 Agent 自查替代。
- 并发边界：创建前会校验远端来源，但不对校验后其他用户或自动化进程的远端写入施加跨平台原子锁。

## 3. 验收例子

### PASS 后执行远端写入
- 触发: 操作 调用 `/skill:git-push` 提交一个有本地改动的分支，并让 `pre-reviewer` 返回 PASS
- Given: 仓库预检、项目验证和提交确认均已通过，当前分支允许推送且没有已有 PR/MR
- When: 用户批准创建本地提交并继续完整提交过程
- Then: 界面依次显示本地 commit 完成、`pre-reviewer` 返回 PASS、远端 push 完成和 PR/MR 创建完成，且审查完成前没有远端写入

### FAIL 阻断远端写入
- 触发: 操作 调用 `/skill:git-push` 并让 `pre-reviewer` 返回 FAIL
- Given: 本地 commit 已成功创建，远端尚未包含该提交
- When: `pre-reviewer` 给出 FAIL 结论
- Then: 流程显示审查失败并停止，本地 commit 保留，远端分支和 PR/MR 列表均未变化

### 非明确 PASS 阻断远端写入
- 触发: 操作 调用 `/skill:git-push`，但 `pre-reviewer` 不可用、执行失败或结束时没有明确 PASS
- Given: 本地 commit 已成功创建，远端尚未包含该提交
- When: 系统无法取得明确 PASS
- Then: 流程显示停止原因，本地 commit 保留，push 和 PR/MR 创建均未执行

### 内容变化使 PASS 失效
- 触发: 操作 在 `pre-reviewer` 返回 PASS 后、push 前改变待推送内容
- Given: 当前内容已经取得一次 PASS，尚未执行任何远端写入
- When: 当前提交标识、已跟踪改动或未跟踪文件中的任一项发生变化
- Then: 原 PASS 不再允许远端写入，界面在 push 前再次显示 `pre-reviewer` 对变化后的完整内容进行审查

### 不再调用已删除流程
- 触发: 操作 在未安装已删除推送前审查流程的环境中调用 `/skill:git-push`
- Given: `pre-reviewer` 可用，仓库预检、项目验证和提交确认均已通过
- When: 本地 commit 创建完成并进入推送前审查
- Then: 系统直接启动 `pre-reviewer`，不显示已删除流程缺失或不可用的错误

### 分支竞态不推送未审提交
- 触发: 操作 在最终快照复核后、push 执行前推进当前本地分支
- Given: 提交 A 已取得有效 PASS，最终快照复核完成，当前分支随后新增未审提交 B
- When: 系统执行远端 push
- Then: 远端来源分支接收的提交为 A 而不是 B，且系统在创建 PR/MR 前检测到当前本地状态变化并使 A 的 PASS 对后续变化失效

### 远端来源不一致时停止创建
- 触发: 操作 在创建 PR/MR 前让远端来源分支不再指向已审提交
- Given: 提交 A 已取得有效 PASS，远端来源分支当前指向其他提交
- When: 系统准备创建 PR/MR
- Then: 系统显示远端来源提交不一致并停止，PR/MR 列表未变化
