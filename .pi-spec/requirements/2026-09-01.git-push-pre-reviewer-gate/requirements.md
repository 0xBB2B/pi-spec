# Git 推送前强制 PR 审查

## 1. 背景

提交 PR 或 MR 的流程仍会尝试启动一个已经删除的推送前审查流程，导致本地提交即使已完成也无法继续推送。现有的只读 PR 前审查者能够检查当前分支相对基线的完整改动，但提交流程尚未把它作为远端写入前的强制门禁。问题解决后，用户在提交 PR 或 MR 时会先看到该审查者的明确结论，只有审查通过且待推送内容未变化，流程才会修改远端。

## 2. 目标与非目标

### 非目标

- 不改变只读 PR 前审查者自身的审查标准、工具权限或输出格式。
- 不改变本地提交创建前的仓库检查、项目验证和用户确认步骤。
- 不修改历史会话、历史任务或历史运行证据中的旧流程名称。
- 不在审查失败后自动修改代码、自动重试或绕过审查。
- 不要求在远端身份校验与托管平台完成 PR/MR 创建之间，对其他用户或自动化进程施加原子写入锁。

### 目标

- 每次向远端推送提交或创建 PR/MR 前，强制完成一次只读 PR 前审查。
- 审查未明确通过时，远端推送和 PR/MR 创建次数均为 0。
- 远端推送的提交应与取得有效 PASS 的本地提交完全一致。
- PR/MR 创建前，远端来源分支应指向取得有效 PASS 的本地提交。
- 当前有效提交规则中已删除审查流程名称的残留数为 0。

## 3. 术语

| 术语 | 定义 |
|---|---|
| 只读 PR 前审查者 | 名称为 `pre-reviewer` 的独立审查角色，检查当前分支完整改动并明确返回 PASS 或 FAIL。 |
| 待推送内容 | 当前提交标识、相对当前提交的已跟踪改动，以及未跟踪文件共同构成的本地状态。 |
| 远端写入 | 向远端仓库推送提交，或在托管平台创建 PR/MR。 |

## 4. 需求

### R-1 固定推送前审查顺序

当本地提交准备完成并即将发生远端写入时，系统应先启动 `pre-reviewer`，且在审查完成前不得推送提交或创建 PR/MR。

### R-2 审查通过后方可写入远端

当 `pre-reviewer` 明确返回 PASS 且待推送内容保持不变时，系统应允许继续推送提交并创建 PR/MR。

### R-3 审查未通过时阻断远端写入

如果 `pre-reviewer` 返回 FAIL、未明确返回 PASS、不可用或执行失败，系统应保留本地提交并停止流程，不得推送提交或创建 PR/MR。

### R-4 内容变化后重新审查

当 `pre-reviewer` 返回 PASS 后待推送内容发生变化时，系统应使原审查结论失效，并在任何远端写入前重新启动 `pre-reviewer`。

### R-5 移除已删除流程依赖

当用户启动 PR/MR 提交流程时，系统应仅使用 `pre-reviewer` 执行强制审查，不得尝试启动已删除的推送前审查流程。

### R-6 推送已审提交

当系统向远端推送时，系统应以取得有效 PASS 的提交标识作为推送来源，不得因当前分支随后变化而推送未审提交。

### R-7 创建前确认远端来源

当系统准备创建 PR/MR 时，系统应确认远端来源分支唯一指向取得有效 PASS 的提交；如果无法确认或两者不一致，系统应停止且不得创建 PR/MR。

## 5. 行为方案

用户启动 PR/MR 提交流程并确认提交内容后，系统完成本地提交，记录当前待推送内容，随后显示 `pre-reviewer` 正在审查。审查者明确返回 PASS 后，系统再次确认待推送内容没有变化，并以该已审提交作为固定来源执行推送。推送完成后，系统在创建 PR/MR 前确认远端来源分支仍指向该已审提交。若审查返回 FAIL、没有明确 PASS、无法启动或执行失败，或者远端来源无法确认或不一致，系统保留本地提交并显示停止原因。若审查通过后本地内容发生变化，系统先重新完成提交与审查，再决定是否继续。

## 6. 边界与已知坑

- 数据量与并发：一次 PR/MR 提交流程只允许一个有效审查结论；不得并发启动多个审查后任选一个结果继续。
- 失败与重试：审查失败后不自动重试；用户处理问题并再次发起后，必须重新执行完整审查。
- 上下游约束：托管平台认证、远端权限和项目验证仍按既有提交规则处理，均不能替代 `pre-reviewer` 的 PASS；标准 PR/MR 创建接口使用远端分支名，不提供跨平台的外部写入者原子锁。
- 已知坑：本地 commit 可以在审查前创建，但任何远端写入都必须发生在有效 PASS 之后；实际 push 来源必须绑定已审提交，不能在执行时重新解析可变的当前分支。

## 7. 验收标准

### AC-1 PASS 后执行远端写入  ← R-1, R-2
- 触发: 操作 调用 `/skill:git-push` 提交一个有本地改动的分支，并让 `pre-reviewer` 返回 PASS
- Given: 仓库预检、项目验证和提交确认均已通过，当前分支允许推送且没有已有 PR/MR
- When: 用户批准创建本地提交并继续完整提交过程
- Then: 界面依次显示本地 commit 完成、`pre-reviewer` 返回 PASS、远端 push 完成和 PR/MR 创建完成，且审查完成前没有远端写入

### AC-2 FAIL 阻断远端写入  ← R-3
- 触发: 操作 调用 `/skill:git-push` 并让 `pre-reviewer` 返回 FAIL
- Given: 本地 commit 已成功创建，远端尚未包含该提交
- When: `pre-reviewer` 给出 FAIL 结论
- Then: 流程显示审查失败并停止，本地 commit 保留，远端分支和 PR/MR 列表均未变化

### AC-3 非明确 PASS 阻断远端写入  ← R-3
- 触发: 操作 调用 `/skill:git-push`，但 `pre-reviewer` 不可用、执行失败或结束时没有明确 PASS
- Given: 本地 commit 已成功创建，远端尚未包含该提交
- When: 系统无法取得明确 PASS
- Then: 流程显示停止原因，本地 commit 保留，push 和 PR/MR 创建均未执行

### AC-4 内容变化使 PASS 失效  ← R-4
- 触发: 操作 在 `pre-reviewer` 返回 PASS 后、push 前改变待推送内容
- Given: 当前内容已经取得一次 PASS，尚未执行任何远端写入
- When: 当前提交标识、已跟踪改动或未跟踪文件中的任一项发生变化
- Then: 原 PASS 不再允许远端写入，界面在 push 前再次显示 `pre-reviewer` 对变化后的完整内容进行审查

### AC-5 不再调用已删除流程  ← R-5
- 触发: 操作 在未安装已删除推送前审查流程的环境中调用 `/skill:git-push`
- Given: `pre-reviewer` 可用，仓库预检、项目验证和提交确认均已通过
- When: 本地 commit 创建完成并进入推送前审查
- Then: 系统直接启动 `pre-reviewer`，不显示已删除流程缺失或不可用的错误

### AC-6 分支竞态不推送未审提交  ← R-6
- 触发: 操作 在最终快照复核后、push 执行前推进当前本地分支
- Given: 提交 A 已取得有效 PASS，最终快照复核完成，当前分支随后新增未审提交 B
- When: 系统执行远端 push
- Then: 远端来源分支接收的提交为 A 而不是 B，且系统在创建 PR/MR 前检测到当前本地状态变化并使 A 的 PASS 对后续变化失效

### AC-7 远端来源不一致时停止创建  ← R-7
- 触发: 操作 在创建 PR/MR 前让远端来源分支不再指向已审提交
- Given: 提交 A 已取得有效 PASS，远端来源分支当前指向其他提交
- When: 系统准备创建 PR/MR
- Then: 系统显示远端来源提交不一致并停止，PR/MR 列表未变化
