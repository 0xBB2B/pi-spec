# 决策许可写入门禁

## 1. 背景

需求级决策台账已经存在，但追加决定只有一个程序接口，没有供主 agent 使用的记录工具；已记录的决定也不会转化为任何强制约束，主 agent 与可写子 Agent 仍能在没有对应决定的情况下修改文件。此前一次实现尝试在三轮审查后因作用域绑定不完整、许可可被绕过而回滚。问题解决后，每条材料性决定通过唯一的记录工具落入台账并返回可核对的回执；一条决定生成一个有界许可覆盖其后的机械写入；缺少有效许可的受保护动作在执行前被阻断，三个审查角色始终不持有写许可。

## 2. 目标与非目标

### 非目标

- 不拦截当前 agent 运行环境之外的进程写入。
- 不为同一已形成决定所授权的每个工具调用重复创建决策记录。
- 不要求安装 Pi 自身运行环境之外的额外语言运行时。
- 不改变三个审查角色的只读职责边界。

### 目标

- 材料性决定通过记录工具以外的途径进入台账的次数为 0。
- 缺少有效决策许可、许可过期或操作超出许可范围时，实际写入次数为 0。
- 同一决定授权的多次机械写入产生的额外决策记录数为 0。
- 在仅具备 Pi 自身运行环境的全新环境中，门禁启动失败次数为 0。

## 3. 术语

| 术语 | 定义 |
|---|---|
| 材料性决定 | 存在合理替代方案、已选定一个方案准备执行，且该选择会改变行为、范围、授权、架构、风险、恢复路径或流程分支的选择。 |
| 决策许可 | 由一条已持久化决定生成的有界执行授权，限定任务、工具、文件范围和有效期，可覆盖该决定下的多次机械动作。 |
| 受保护动作 | 修改文件、执行验证命令、启动可写子 Agent 以及远端写入。 |
| 回执 | 记录工具在成功追加后返回的对象，含台账路径、行号与该行内容哈希，可与台账逐行核对。 |

## 4. 需求

### R-1 决策记录工具是唯一追加入口

当 AI 或用户形成材料性决定时，系统应仅通过受材料性检查保护的决策记录工具向对应需求台账追加恰好一行，并返回可与该行核对的回执。

### R-2 决策许可覆盖机械动作

当一条已记录决定授权同一任务范围内的多个机械执行步骤时，系统应使用一个有界决策许可覆盖这些步骤，不得为每个工具调用重复创建决策记录；目标、工具、文件范围或有效期变化时，原许可应失效。

### R-3 无有效决策许可时阻断写入

如果主 agent 或可写子 Agent 尝试执行受保护动作时许可缺失、无效、过期或与操作范围不匹配，系统应在动作执行前阻断并显示原因。

### R-4 审查者不持有修复写许可

当 `review-engineer`、`pre-reviewer` 或 `acceptance-reviewer` 执行审查时，系统应禁止其修改生产代码、测试、需求或其他交付物；`acceptance-reviewer` 仅可在既有任务许可下写入指定验收报告。

### R-5 安装包不依赖额外语言运行时

当系统以可安装包形式提供决策门禁时，系统应仅依赖 Pi 自身已有运行环境；缺少非必需外部程序不得影响门禁启动。

## 5. 行为方案

主 agent 形成材料性决定后调用记录工具，工具检查材料性字段，向对应需求台账追加一行并返回回执；工具拒绝或追加失败时主 agent 不执行关联动作。持有回执的决定可申请一个许可，许可声明任务、允许的工具、文件范围与有效期。此后受保护动作在执行前先核对许可：范围内的写入正常执行且不再产生新的决策记录；缺少许可、许可过期或目标超出范围的动作被阻断，界面显示缺少许可或范围不匹配。可写子 Agent 启动时继承父级为其签发的有界许可，三个审查角色不获得任何写许可，`acceptance-reviewer` 只获得覆盖指定验收报告的许可。全新环境安装本包后，门禁只依赖 Pi 自身运行环境即可进入 ready 状态。

## 6. 边界与已知坑

- 数据量与并发：同一需求台账的追加串行化；并发申请许可各自独立。
- 失败与重试：记录工具追加失败或回执与台账不一致时不重试，关联动作停止；许可核对失败的动作不自动重试。
- 强制边界：门禁只能约束由当前 agent 运行环境发起的受保护工具调用，无法拦截运行环境之外的进程写入；任何可写子 Agent 必须加载同一门禁。
- 上下游约束：许可范围必须绑定任务清单中该任务声明的文件集与验证命令，不能接受调用方自报的任意范围。
- 已知坑：许可核对与实际写入之间若存在时间窗，目标路径可被替换绕过范围检查，核对必须落在实际写入的同一步骤；许可签发若不绑定任务文件集，越界写入无法被识别；把 readiness 与任何外部程序绑定会让缺少该程序的环境无法启动门禁。

## 7. 验收标准

### AC-1 记录工具追加并返回回执  ← R-1
- 触发: 操作 通过决策记录工具追加一条材料性 AI 决定
- Given: 对应需求台账可写且为合法追加式记录
- When: 工具调用完成
- Then: 对应台账恰好增加一行，返回的回执含台账路径、行号与该行内容哈希，且与台账内容逐项一致；材料性字段不完整的调用被拒绝且台账不变

### AC-2 同一决定不重复记录机械写入  ← R-2
- 触发: 操作 用户批准一个包含 5 个文件修改和 3 条验证命令的任务
- Given: 一条用户授权决定已成功记录并生成覆盖该任务文件与工具的有效许可
- When: Agent 按计划完成全部修改和验证
- Then: 用户决策台账只增加授权决定一行，AI 决策台账没有因机械工具调用增加记录，全部许可范围内动作正常执行

### AC-3 无许可和越界操作被强制阻断  ← R-3
- 触发: 操作 依次尝试一次没有决策许可的文件修改，以及一次使用有效许可但目标文件超出范围的修改
- Given: 受保护动作尚未产生文件副作用
- When: 主 agent 发起两次操作
- Then: 两次操作都在执行前被阻断并显示缺少许可或范围不匹配，目标文件内容保持不变

### AC-4 子 Agent 和 reviewer 同样受门禁保护  ← R-3, R-4
- 触发: 操作 让 Test 或 Impl 子 Agent 在没有有效许可时修改文件，让 `review-engineer` 或 `pre-reviewer` 尝试修改文件，并让 `acceptance-reviewer` 写指定报告后再尝试修改生产文件
- Given: 各角色已按职责加载，验收任务已有仅覆盖指定报告的许可
- When: Agent 发起对应写操作
- Then: Test/Impl 的无许可写入被阻断，两个只读 reviewer 的修改失败，`acceptance-reviewer` 只能写指定报告且生产文件修改失败

### AC-5 无额外语言运行时也能启动门禁  ← R-5
- 触发: 操作 在仅具备 Pi 自身运行环境的全新环境中安装并启动本包
- Given: 环境没有安装任何非必需的额外语言运行时
- When: 系统加载决策门禁并执行 readiness 检查
- Then: 门禁成功进入 ready 状态，受保护工具可按有效决策许可运行，界面没有显示缺少额外语言运行时
