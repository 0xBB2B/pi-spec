# 决策记录工具与流程触发点

## 1. 背景

每个需求目录都有 AI 与用户两个决策台账，格式与材料性判定已经定义，但主 agent 没有可调用的追加工具，流程文件里也没有任何一步要求记录。结果是台账在需求创建后一直为空，AI 自主做出的归因与方案选择、用户给出的确认与取舍都没有留痕。问题解决后，主 agent 在流程中每形成一个材料性决定，先通过唯一的记录工具写入对应台账并拿到回执，再执行动作；台账追加失败时动作不执行。

## 2. 目标与非目标

### 非目标

- 不做决策许可、写入拦截或任何强制门禁。
- 不记录观察、测试结果、审查结论、机械执行步骤、固定状态转换、临时想法或未形成选择的问题。
- 不把台账内容注入子 Agent 的提示。

### 目标

- 主 agent 通过记录工具以外的途径写入台账的次数为 0。
- 流程中形成的材料性 AI 决定与用户决定在动作执行前落入对应台账的比例为 100%。
- 记录失败后仍执行关联动作的次数为 0。

## 3. 术语

| 术语 | 定义 |
|---|---|
| 材料性决定 | 存在合理替代方案、已选定一个方案准备执行，且该选择会改变行为、范围、授权、架构、风险、恢复路径或流程分支的选择。 |
| AI 决定 | 主 agent 自主形成的材料性决定，例如问题归因、修复路径、备选方案取舍。 |
| 用户决定 | 用户回答提问或主动给出后形成的材料性选择，例如确认需求、选择方案、限定范围。 |
| 回执 | 记录工具在成功追加后返回的对象，含台账路径、行号与该行内容哈希。 |

## 4. 需求

### R-1 记录工具是唯一追加入口

系统应提供一个决策记录工具，接收需求目录、决定人、触发、决定、依据、备选方案与影响等字段，经材料性检查后向对应台账追加恰好一行并返回回执；不提供其他追加途径。

### R-2 流程决策点在动作前记录

当主 agent 在需求确认、并行组确认、修订归因、方案取舍、需求接受或作废等流程节点形成材料性决定时，系统应在执行该决定对应的动作前调用记录工具，AI 自主形成的写入 AI 台账，用户形成的写入用户台账。

### R-3 未形成选择的问题不记录

当用户忽略、取消或未回答一个问题时，系统应不写入任何台账行，并在用户随后形成明确选择时只追加一行。

### R-4 记录失败时停止

如果记录工具拒绝输入、追加失败或回执与台账不一致，系统应停止执行该决定关联的动作并显示原因。

## 5. 行为方案

主 agent 走到流程决策点并形成材料性决定后，先调用记录工具，传入需求目录、决定人、触发、决定与备选方案，AI 决定另附依据与后续动作，用户决定另附影响。工具检查材料性字段与决定人专属字段，追加一行到对应台账，返回含行号与哈希的回执。主 agent 收到回执后才执行动作；工具报错或无回执时停止并把原因展示给用户。用户未回答的问题不产生任何调用。

## 6. 边界与已知坑

- 数据量与并发：同一需求的追加串行化，并发调用按到达顺序依次落盘。
- 失败与重试：追加失败不自动重试，关联动作停止，由用户决定是否重新触发。
- 上下游约束：记录工具只在主 agent 会话中可用；子 Agent 不加载它，子 Agent 内部的选择由主 agent 在派工前后归入自己的决定。
- 已知坑：只加工具不改流程文件，主 agent 仍然不会调用；只在一个节点写触发而漏掉其他节点，台账会残缺。触发点必须逐一写进对应流程步骤。

## 7. 验收标准

### AC-1 记录 AI 决定并返回回执  ← R-1
- 触发: 操作 主 agent 通过记录工具追加一条含依据与后续动作的 AI 决定
- Given: 需求目录的两个台账存在且合法
- When: 工具调用完成
- Then: AI 台账恰好增加一行且字段完整，用户台账不变，返回的回执含台账路径、行号与该行哈希并与台账内容一致

### AC-2 记录用户决定  ← R-1
- 触发: 操作 主 agent 通过记录工具追加一条含影响的用户决定
- Given: 需求目录的两个台账存在且合法
- When: 工具调用完成
- Then: 用户台账恰好增加一行，AI 台账不变；缺少影响或附带依据字段的用户决定被拒绝且两个台账不变

### AC-3 需求确认前写入用户决定  ← R-2
- 触发: 操作 用户在澄清结束后确认需求文档
- Given: 需求处于 draft 且两个台账为空
- When: 主 agent 准备把状态推进为 confirmed
- Then: 状态变更前用户台账已出现一行确认决定，随后状态才变为 confirmed

### AC-4 修订归因前写入 AI 决定  ← R-2
- 触发: 操作 用户报告一个结果与预期不符的问题
- Given: 主 agent 已复现并把根因归为实现缺陷、规范缺陷或需求变更之一
- When: 主 agent 准备按归因进入修正流程
- Then: 进入修正前 AI 台账已出现一行含归因、依据与被否定备选的决定

### AC-5 未回答的问题不留痕  ← R-3
- 触发: 操作 主 agent 提出一个方案选择问题，用户取消
- Given: 两个台账处于已知行数
- When: 问题被取消，随后用户主动给出明确选择
- Then: 取消时两个台账行数不变；用户给出选择后用户台账只增加一行

### AC-6 记录失败阻断动作  ← R-4
- 触发: 操作 在用户台账被写入一行非法内容后，让用户确认需求
- Given: 记录工具会因台账非法而拒绝追加
- When: 主 agent 调用记录工具
- Then: 界面显示台账非法的原因，需求状态保持 draft，台账内容保持不变
